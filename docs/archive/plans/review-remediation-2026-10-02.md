### 用户追加故障：切换标签残留关系溯源

现象：同一详情里重复出现“关系溯源 / 未找到关系”，并非只是单一区块变高。
当前代码的 TagRelationTree 和 LiveTagPool 提供的管理员 extraDetails
都是同一 Fragment 的直接兄弟，key 都等于 selected.id。
切换标签时发生身份冲突，真实 React DOM 会留下旧的关系树。

旧 TagPoolBrowser 切换用例没有传入 extraDetails，缺少触发条件；
最初 LiveTagPool 测试还把 TagRelationTree 替换为 null，只暴露警告而没检查残留。
此次补全管理员详情及真实关系树后，两个入口均复现切换一次区块从 1 个变成 2 个。
此前对开发服务器或 CSS 的排查不能替代这一源码可复现根因；
本次没有改 CSS、树结构、用户既有改动或终止服务器。

修复：关系树 key 改为 `relations:${selected.id}`，
既与管理员详情身份区分，也保留切换标签时重建局部折叠状态的行为。
仅此一处生产代码修改，不增加状态、清 DOM、effect 或隐藏旧节点的 CSS。

验证：TagPoolBrowser、LiveTagPool、TagRelationTree 三文件 11/11 通过，
